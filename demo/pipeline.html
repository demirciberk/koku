koku · how it was built

A Turkish perfume assistant, distilled on one laptop GPU

The perfume data is in English; people search in Turkish, and mostly by feeling ("something for a first date") rather than by note. koku closes that gap with one local teacher model that writes Turkish training data, and two small models that learn from it. No API keys, no cloud GPU: an RTX 4060 with 8 GB.

01 / PipelineOne teacher, two students

Qwen3-8B runs locally through llama.cpp and writes, for every perfume, a short Turkish description and three Turkish search queries: one about notes, one about style, one only about the occasion or feeling. A rule-based filter drops bad rows. The clean data trains a retriever (which perfume matches this query) and a small language model (describe this perfume in Turkish).

02 / Evaluation firstMeasure before training anything

Before any model, I wrote 183 Turkish queries and gave each one machine-checkable constraints (accords, notes, gender) instead of hand-picked answers, so relevance is reproducible. The retriever only ever sees the query text; a test guards that. Keyword search barely works: most Turkish queries share no word with the English data.

03 / Synthetic dataThe teacher, and what had to be fixed

Two pilot runs showed real problems. The teacher mistranslated note names (peony became "pony") and invented notes, so it now receives Turkish names from a fixed 300-note table. A third of its occasion queries started with the same phrase, so each perfume gets one of six angles (a moment, a gift, a feeling, a place, something to avoid, a routine). The full run took 6.4 hours with zero malformed outputs; the filter then removed 498 rows.

04 / RetrievalWhere the gains came from

The biggest single step was not a model at all: translating note and accord names into Turkish doubled the score. Adding the teacher's description to each perfume added 19%, and fine-tuning BGE-M3 on 37,677 teacher query-perfume pairs added another 12%.

That last result is the honest headline: the teacher's occasion queries were repetitive, so the retriever had little new to learn about situations. More varied occasion data is the next lever, not more epochs.

05 / DistillationFrom 8B to 0.6B

Qwen3-0.6B was trained with LoRA to reproduce the teacher's output (sequence-level distillation, about 45 minutes). On 200 perfumes it never saw, the untuned model produced no usable output; the trained one follows the format every time and invents fewer notes than its teacher, because it learned to stay close to the input list.

06 / InferenceQuantizing for the browser

The merged student was converted to GGUF and quantized. Q8_0 loses nothing; Q4_K_M is a third of the size for about 4% lower agreement with the teacher. At this model size Q8 and Q4 run at nearly the same speed, so smaller weights stop paying off.

07 / LimitsWhat is not solved

  • The evaluation queries were drafted with an LLM and have not been reviewed by a person yet.
  • Occasion labels map feelings to accords by judgement; they are the least objective part of the set.
  • The student inherits the teacher's repetitive occasion phrasing.
